# Rencana implementasi: dekomposisi prompt evidence-first

## Tujuan dan keputusan
Mengurangi beban satu prompt monolitik di `extractDocumentGroups` dengan pekerjaan semantik yang lebih sempit dan satu model LLM yang sama. Gunakan sumber/parser/validator/checkpoint yang ada. Hasil eksperimen C mendukung deterministic-first XLSX tetapi tidak membuktikan seluruh kontrak produksi; jangan salin aturan spesifik fixture sebagai asumsi global.

## Acceptance criteria
1. Ganti prompt ekstraksi grup monolitik secara nyata menjadi tugas yang lebih sempit; setiap grup tetap mengevaluasi semua domain yang relevan tanpa menjadikan document type sebagai filter. Rekonstruksi bentuk GroupExtraction lengkap dan jalankan validator fail-closed yang sama (atau lebih ketat), jaga sumber/ID/period/scope, output per grup, summary, health, facts, alerts, actions, cost, assurance, metadata, sheet interpretation. Model tidak mengarang kutipan atau locators. Jangan mengklaim sukses dari stub atau placeholder.
2. Satu model provider yang sama; tidak ada provider pool atau consensus spekulatif. Kegagalan salah satu tugas tidak boleh menjadi array kosong/absent. 429, retry, concurrency, cancellation/fencing dan checkpoint tidak boleh membuat dokumen tampak lengkap secara salah atau membebani ulang hasil completed yang valid. Versioning cache harus mencegah hasil monolitik lama disalahartikan; jika task-level checkpoint dibutuhkan, implementasikan kontrak dan migrasi secara benar.
3. Pertahankan evidence-led extraction dan semantik formula/cache. Unknown/review yang sah tidak diubah jadi fakta, ID yang dikutip harus diizinkan untuk grup/tugas dan ditetapkan server. Input tidak tepercaya. Jangan terapkan RAG atau klasifikasi issue/risk fixture sebagai aturan universal.
4. Deterministik-first hanya bila dapat mempertahankan seluruh perilaku dan keamanan kontrak; jangan mengklaim jalur C penuh atau cakupan field di luar yang benar-benar diterapkan/dibuktikan. Jangan mengubah dokumen pengguna/fixtures.
5. Buktikan melalui tes perilaku pada seam `extractDocumentGroups` (mock provider + checkpoint store; kelompok campuran, cross-domain, sitasi salah, kegagalan parsial/retry, cache dan 429), tes legacy relevan, typecheck dan smoke menjalankan parser produksi dan ekstraksi pada data fixture dengan provider mock. Tidak menambah tes source-string/wiring/incidental; jangan melemahkan validasi atau tes kualitas untuk hijau. Pastikan pembuktian menunjukkan perubahan tugas/prompt bukan sekadar format prompt.
6. Ubah `CONTEXT.md` untuk mengatasi kontradiksi dengan aturan lama satu call per grup; ADR hanya jika konvensi repo memerlukan, rujuk tradeoff konteks dan panggilan. Update dokumentasi worker, panggilan terkait dan versi cache. Bersihkan scaffolding.

## Anggaran uji API live
Maksimum 4 HTTP request ke API LLM aplikasi untuk seluruh sesi, termasuk retries, tanpa retry otomatis; maksimum 4096 token output/request dan maksimum 12.000 karakter input/request. Hentikan segera saat 401/403/404/429, output terpotong atau batas; gunakan hanya fixture yang disetujui, tidak pernah kirim expected-results atau secrets. Log hanya model, token input/output jika dilaporkan, status, durasi, hash sumber, hasil validasi; jangan bocorkan API key/konten sensitif. Jika kode tidak dapat enforce batas ini secara menyeluruh atau API tidak dapat diakses, jangan jalankan live test; laporkan blocker. Model pelaksana zcode/GLM terpisah dari API eksperimen.

## Eksekusi dan laporan
Terra sebagai perencana/integration owner; GLM `zcode/glm-5.3-flash` melalui OMP mengerjakan implementasi dan slice dokumen. Penelitian graphify query sebelum grep/read source; update graph setelah kode berubah. Hindari overwrite perubahan user; jangan commit/reset/ubah fixture/kredensial. Laporan akhir harus membedakan bukti mock/live, cakupan kontrak, perubahan nyata, batas budget, masalah tersisa dan tidak mengklaim lebih dari yang diuji.
