# Compare at project and WBS levels with fallback

Assurance supports both project-total and matching WBS/work-package comparisons. When WBS identifiers or comparable values are missing, the WBS result remains an explicit evidence gap while any supported project-total comparison is still available. Schedule variance compares baseline and reported forecast dates only for the same milestone or WBS; progress percentages do not generate forecast dates. Use reported progress values at project or WBS level without calculating a project total from WBS percentages; compare progress across periods only for comparable scope and WBS. Compare reported deliverables or WBS scope with the approved baseline using accepted WBS mappings, presenting additions, removals, or changes as source-backed candidates rather than approved changes. Show Budget, Schedule, and Risk separately rather than calculating one project score; an overall status stated in a source remains a cited source claim. Each comparison uses a PMO-selected review period, and source periods/as-of dates are preserved rather than silently mixing the newest value from each document. Existing Budget thresholds (on-track at <= 0%, attention above 0% through 5%, critical above 5%) and Schedule thresholds (0 days late is on-track, 1–14 days needs attention, more than 14 days is critical) remain in use only for comparable evidence and are versioned. This favors useful partial results without treating incomparable records as equal.

The initial result is shown on the existing Assurance page: evidence-backed domain comparisons, findings, gaps, and source citations. It does not add AI-generated action suggestions or a separate downloadable report.
