## Current authorization

Documentation revision only is authorized. Each implementation batch needs explicit approval of its plan and criteria; D2-D4 also require review of the preceding batch's diff/results. A is display-only, B is frontend-only, and C is deferred integration. No API, request/response, fetching, query, server action, persistence, worker, schema, migration, authorization, or business-rule changes belong to UI batches. Preserve palette/tokens and existing behavior. Historical preservation remains unverified; see the governing spec.

## Batch sequence

- **D1:** Guidance, truthful status wording, and accessibility.
- **D2:** Stable step navigation, state preservation, Evidence review grouping, metadata/source clarity, and existing warnings.
- **D3:** Report editing/lifecycle clarity and sources associated with each Advisor answer.
- **D4:** Existing Assurance/Overview findings, period/history context, and hierarchy.
