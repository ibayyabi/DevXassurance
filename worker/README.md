# Worker

The worker validates file signatures/content, then parses PDF, DOCX, XLSX, PPTX, CSV, TXT, and common image evidence into bounded, source-located chunks. Office and slide tables preserve their row structure; chunks retain page, sheet/row/range, slide, paragraph, or image locations in `document_chunks.parser_metadata` alongside parser version and warnings.

A spreadsheet row longer than one bounded part is split at cell (` | `) boundaries when possible. Only a ` | ` that lies exactly between two located cell tokens is treated as a separator; the same characters inside a cell's own value are literal content and are never skipped. A per-cell source reference and its sibling `rowCells` are retained only in the part that fully contains that cell's own text; a cell crossing a part boundary, a cell that cannot be located once, or a row that alone exceeds the per-chunk reference budget stays citable at row level instead of being attributed to evidence the part does not contain. Row references are retained first, and the per-chunk budget is checked before a block is added so retained row references never grow a chunk past 120 references. Splitting never creates a synthetic cell identity or moves a cell reference into another part.

XLSX formula cells retain their formula, cache status, raw cached result/type, and sheet/cell locator in `parser_metadata`. The worker verifies a supported subset of self-contained arithmetic formulas against their cached values; a mismatch requires review. Other stored caches are not freshness proof and remain source-reported candidates. Cached cost values retain their raw wording but are not normalized or comparable, and formula-derived dates/statuses are not accepted as current. Missing, empty, error, or unknown results require review. Unresolved formula cells cannot support extracted facts, alerts, actions, group metadata, health status, or risk snapshots. Cached formula cells cannot support current risk snapshots, alerts, or actions either. Exact single-cell citations inspect that cell's formula cache only, while row/table citations conservatively consider every matching value cell and remain disqualifying when an unresolved formula is in scope. Ambiguous worksheet groups may include a candidate-only interpretation in the existing bounded extraction request; its header, column, and observation citations resolve to parser-authored ranges and never become an approved mapping. Repeated non-empty header labels in unrelated columns are diagnosed as `duplicate_header` and remain raw evidence for review; one merged header range repeating its value is not treated as a duplicate. A two-row header is recognized only when the first row is a proven week/period grid or a merged group-header row and the second row reads as labels (short textual, non-numeric values), with date continuations allowed only in columns the proven week row already labelled; otherwise the candidate row stays data, so an ordinary header followed by an all-text first data row is not consumed or lost. A staggered label row that repeats a label stays data. A week/date header row directly above a textual WBS header row still works, so the weekly grid does not force an assumed column mapping. Rows that stop matching their declared header are detected per row as layout drift (document-parser/23): a labelled column's cell-class profile is anchored on the rows closest to the header, and a row whose value-type pattern conflicts with that profile in at least two columns — a currency-formatted number inside a text column counts double, the signature of a price typed into a unit or specification column — renders without column-role labels, so its values stay citable as raw unattributed evidence while every column-role claim against it is refused by the standing gates, and a `layout_drift` parser warning names the drifted row ranges and routes the document to review. Calendar structure never drives detection: date-profiled columns are wildcards and date-valued cells never conflict (week/Gantt grids legitimately mix dates, notes, and empty cells), a header that is one label repeated across every column is a title banner declaring no roles, and when the header-adjacent rows disagree with their own profile the detection stays off, so all three cases keep today's behavior instead of flagging ordinary grid variety.

Validated PMO cost and assurance observations retain the cited cell location when available; older references without a cell location fall back to their source chunk. Per-cell references do not make an unresolved formula usable or establish complete domain coverage.

XLSX percentages require explicit unit evidence: either an unambiguous own number format (a plain `0%`/`0.00%` section; not an escaped `\%`, quoted `"%"`, or sectioned/currency format) or a unique matching cell under a percent-labeled progress column such as `Actual %`, `Progress %`, or `Realisasi %`; risk probability/likelihood columns do not establish progress. Each stored progress row also carries a `measure_kind` decided only by the cited source itself: the cited cell's own header label (or, for narrative sources, the cited statement) must explicitly say planned (`Planned %`, `Rencana %`) or actual (`Actual %`, `Realisasi %`); a generic `Progress %` header, the row's other columns, the document role, and the magnitude never decide it, and a model-claimed kind the citation does not prove is dropped as a quality warning. Planned and actual values on the same row are separate entries with separate cell citations, so W4/W5 `Planned %` (C7/C8) and `Actual %` (D7/D8) are each preserved with their own provenance. A General-formatted `12.5` under `Actual %` means `12.5%`, while `0.125` means `0.125%`; magnitude never triggers fraction scaling. Cells whose own number format proves scaling render the stored fraction as its exact percentage (`0.125` → `12.5%`, not Excel's rounded display) beside the unchanged `[raw value: 0.125; number format: 0%]` annotation, so the raw value stays traceable. XLSX citation text for a cell or row always begins with the readable text the model was shown, so a model-visible excerpt stays verifiable against the canonical source a citation must match. Narrative (non-XLSX) progress is accepted only when the cited statement explicitly labels that percentage as work progress, completion, or actual-reported work (English or Indonesian wording such as `progress`, `completion`, `actual`, `realisasi`, or `kemajuan`, with at most a few plain words between the label and the percentage); when the statement names a risk likelihood/rating or financial/payment metric anywhere in the same clause or field, the percentage remains a gap unless it sits in its own delimited progress field (for example `Risk: high, Project progress: 25%` holds while `Pembayaran dari penyedia proyek yang sudah selesai 80% dari nilai kontrak` or `Actual: 45% of budget has been spent` stays a gap); an unrelated-clause percentage or an unclear percentage remains a gap.
When structured cell metadata is unavailable, a percentage may still use a citation only if it points to one exact XLSX cell whose own literal text contains a progress cue and explicit percentage; formula cells, full-row citations, risk text, and sibling-cell context never satisfy this fallback.

Progress `period_basis` is derived from exact cited value-cell headers: explicit cumulative/to-date, weekly, monthly, or daily cues retain that basis. Neutral headers stay unproven unless the exact same XLSX row contains a parser-verified `Variance` formula that subtracts exactly the cited Actual % cell minus the cited Planned % cell; the formula expression establishes structure only, never its cached result. Narrative and legacy rows without an explicit basis stay unassessed. Computed status requires equal source-backed period labels and equal proven bases at the current cut-off; formula-paired observations must also cite distinct value cells from the same document, content hash, sheet, and row. Mismatches and unproven pairs retain both sources but produce no variance.
Historical progress deltas use only source-backed, earlier current-role rows as prior snapshots, and compare only matching scope, measure kind, normalized percentage unit, and proven measurement basis. Baseline-role rows remain the approved baseline even when dated; future or undated current-role rows remain gaps and cannot satisfy the current cut-off.

Source-reported progress RAG is stored only as a literal, cited claim from the same exact row/cut-off as its progress value; it is never computed by the worker. Formula-backed RAG remains a source claim but is marked freshness-unverified because the cache is not proof of freshness. The application keeps this claim separate from computed status, which is unassessed without an approved, versioned per-project rule; it never applies global thresholds or rolls WBS values into a project total.

The current database boundary grants authenticated users read-only access to these rules; creation and supersession require privileged `service_role` provisioning. No reviewer-facing rule write RPC or UI is provided.

A cost observation's period label and cut-off date must appear in the cited source, exactly like assurance observations; a period or date read from another cell or snapshot is excluded instead of trusted. For non-spreadsheet narrative, record and due dates need explicit role cues; an approved-baseline cost may also use an explicit approval date tied to its amount in the same clause. A period needs either a labelled period value or one period directly attached to the cited amount/progress in the same clause (for example, `for October 2026` or `8% — June 2026`); mere occurrence of a date or period string is not enough.

An XLSX date is linked through parser row/column/header metadata, and each observation field decides which column is admissible. An `as_of_date` is accepted only when the cited row has exactly one cut-off/record-date column and the claimed date equals its normalized value; due/target/start/mitigation columns are not record dates. A milestone date or mitigation due date is accepted from a due/target/plan/baseline/actual column and rejected when it comes from the record-date column. A milestone `raw_date` that matches a due-column cell only proves that cell's role, not freshness: when that cell is a stored formula result, the derived date remains a source-reported candidate for review (`formula_cache_review_required`) instead of being accepted as a fresh milestone date. XLSX `period_label` is accepted only when the cited row or cell has exactly one parser-labelled period column and its value exactly matches; per-cell citations carry the row's sibling cells so date and period ambiguity checks remain effective. Missing, mismatched, or ambiguous evidence remains a gap. An unlabelled cell, a cell crossing a split boundary, an over-budget row, and older references without structural cell metadata cannot prove a date or period. A milestone date derived from `raw_date` is checked as a due/event date against the same structural row or cell evidence, so a cut-off/report-column value or an unlabelled value cannot become a milestone date even when its raw wording appears in the cited excerpt. Non-spreadsheet record/due dates need an explicit role cue in the same cited clause; only an approved-baseline cost may use an explicit approval date tied to the amount. One cited value may carry both a record and a due/event cue (for example `Reporting date 18 September 2026, milestone due 18 September 2026`); the explicit due/event cue wins, while a record-only value is still rejected as a milestone date. Non-spreadsheet periods may use an explicit field label or one unambiguous period directly associated with the cited value in the same clause.

An XLSX work-package scope may come from a labelled scope column in the cited row or from a workbook-declared subject linked to the cited sheet's exact title cell. The key/value declaration may be on another sheet or extraction group, but `DOCUMENT_CONTEXT_REFERENCES_JSON` exposes its exact key cell, value cell, and title cell as separate source references from the same parsed workbook, each with its own source ID, cell locator, and verbatim model-visible text; reciprocal `paired_source_id` values link only the key and value cells. The model returns the declared value-cell ID as `scope_source_id`; the validator checks the paired key/value cells and requires the cited sheet title to state that value. Repeated declarations with the same normalized subject value are equivalent, and the first fully citable key/value pair is used; multiple distinct subject values matching the title remain ambiguous and supply no declared scope. The worker never fabricates a combined key-plus-value citation or attributes an unlinked scope. Stored `scope_provenance` retains each key, value, and title source ID, exact sheet/cell locator, and canonical excerpt; cost-observation provenance is persisted and exposed by the cost-observation read model, while assurance-observation provenance is not yet read by the assurance read model or review UI (ticket 03). `PARSER_VERSION` and `EXTRACTION_SCHEMA_VERSION` are bumped when these semantics change, so earlier extraction groups are not reused.

These decisions use structure, not incidental words: a worksheet title must come from a standalone title-like literal pre-table cell, optionally sharing its row only with explicit date/period/metadata values, or an identical repeated title block explicitly covered by a merge range, rather than an ordinary table header; a period value must itself look like a period (narrative headers such as “Work Completed This Week” do not count); and a `Task` cell cannot establish WBS scope. Text-formatted ISO dates participate in record-date ambiguity checks. Non-spreadsheet WBS scope requires an explicit scope cue and exact label in the same clause as the cited field's source value; comma or dash separators and the explicit grammatical delimiter `is` can end that scope value, while prefix labels and scope names elsewhere in multi-subject passages cannot be attributed to the cited field. Cost normalization accepts one amount with either one adjacent recognized currency token (including `Rp.`) or one explicit amount label paired with one nearby `Currency` label; unrelated or competing currency mentions leave currency unset. Ambiguous `¥` stays unset; explicit `JPY` or `CNY` is required.
Health snapshots preserve only a literal dimension-specific status field from the cited source. A model cannot infer a RAG status, score, or evidence-coverage percentage; the exact source status text stays distinct from the status field, and a snapshot date must be a cited record date (never a document hint or current date). Snapshots without a verified date are not published, and a `needs_review` result cannot publish a green/amber/red dashboard status.


Image OCR uses local PP-OCRv6 tiny (RapidOCR 3.10.0 on ONNX Runtime CPU 1.31.0); scanned-PDF OCR adds Ghostscript rasterization. The configured PP-OCRv6 route is `id` for Indonesian/English text; it is fixed configuration, not language detection. Indonesian/English quality must pass the human-verified corpus before production. Missing local model assets return `ocr_model_unavailable`, and unreadable scans return `ocr_no_text`; every OCR failure fails the whole document instead of producing successful empty extraction. All scanned page images for one document go to one helper process and one engine initialization.

Local setup (localhost pilot, Python 3.11, macOS/Linux):

```bash
python3.11 -m venv .venv-ocr
.venv-ocr/bin/pip install -r worker/ocr/requirements.txt
.venv-ocr/bin/python worker/ocr/ppocr.py --prefetch
.venv-ocr/bin/python worker/ocr/ppocr.py --check
```

`--prefetch` downloads the pinned assets once and verifies their SHA-256; `--check` verifies local assets and confirms the pinned RapidOCR/ONNX Runtime package versions. JSON helper output records installed runtime versions and model hashes. The request path never downloads models and never falls back to Tesseract. Pinned assets: `PP-OCRv6_det_tiny.onnx` (`f42c0fbd294d95eac1a550e131b277dac97462c8025fa4b6c3cec1b7894bd3d5`), `PP-OCRv6_rec_tiny.onnx` (`e16e242de5937ad92609223f19bc2aff3727ee40b095f996907c24749bad251b`), and `ch_ppocr_mobile_v2.0_cls_mobile.onnx` (`e47acedf663230f8863ff1ab0e64dd2d82b838fceb5957146dab185a89d6215c`).

Set `XASS_OCR_PYTHON` to override the interpreter (default `.venv-ocr/bin/python`) and `XASS_OCR_MODEL_DIR` to override the asset directory (default RapidOCR's package `models` directory). Ghostscript is required for scanned PDFs. PP-OCRv6 tiny is the localhost pilot only. Before future VPS deployment, verify text quality, CPU throughput, and memory against that host's actual limits; a model-size change additionally requires the tiny/small quality gate.

Per-document extraction starts with one document-level classifier call using the internal title, filename, parser metadata, workbook sheet names, and up to 12 bounded source references. It returns one primary artifact type plus an evidence role (`baseline`, `current`, or `supporting`); taxonomy guidance distinguishes periodic progress reports from plans, schedules, and embedded risk registers. A material filename/content mismatch is surfaced as a quality warning without overriding the content-based class. Classifications below 0.7 confidence, missing roles, invalid citations, or conflicting intake hints require review. Each chunk group is extracted by two narrower task calls to the same single configured model, sharing the group's header and exact source references: a group-analysis task (facts, group summary, health snapshots, alerts, actions, group metadata suggestions, and the candidate sheet interpretation) and a domain-evidence task (cost observations plus milestone, progress, and risk assurance observations), both evidence-led over every domain regardless of the artifact type. The worker merges the two task outputs by exact field ownership and runs the unchanged fail-closed `GroupExtraction` validator over the merged result: each required field must come from its owning task (analysis: facts, summary, health snapshots, alerts, actions; domain: cost and assurance observations), a missing owned required field fails the attempt instead of accepting the other task's echo, and optional fields (group metadata suggestions, sheet interpretation) are read only from their owner. An unusable analysis output skips the domain call for that attempt; validator corrections are routed to the task that owns the failing field, and corrections naming no merged field go to both. A task loss, invalid JSON, or validation failure fails the whole group fail-closed and checkpoints it as retryable, never as absent evidence, and the domain task's empty arrays are trusted only after that task completed over the full group. Completed groups checkpoint under the group key and skip both tasks on retry. After all groups validate, one additional provider request synthesizes the persisted executive summary across supported file formats: 1–6 single-line bullets and at most 150 words, prioritizing project/reporting period, status/baseline, critical milestone, top unresolved risk/action, readiness/evidence gaps, and material data-quality caveats. It uses only validated group summaries and selects up to six associated source citations. Detailed facts, alerts, actions, parser warnings, and review status remain separately available. If synthesis cannot be validated, the worker stores an explicit unavailable message, zero confidence, and a review warning; it never concatenates group summaries as a fallback. The model receives compact source references and returns source IDs; the worker resolves each ID to the exact canonical chunk excerpt and global chunk index before persistence. Invalid optional fact rows trigger one same-model correction and, if still invalid, produce an explicit quality warning and `needs_review` rather than discarding independent valid outputs. The service-role-only `document_extraction_groups` key is content-addressed: it binds the group's own chunk texts and locators plus the parser/schema versions — not the document hash and not the group index. Only completed exact-key groups are reused, and the stored result is re-validated against the current group on load, so a next-week workbook whose structure is unchanged reuses its unchanged groups across documents within the project (measured 14–59% of group calls on the demo weekly corpus, ~36% on average) while any edited group re-extracts; failed rows from other documents are never reusable, and groups whose earlier chunk boundaries shifted miss the cache and re-extract. Stored intake hints are loaded with a project-and-document-scoped lookup; AI writes suggestions only, never reviewer-confirmed values. n8n remains the queue/orchestrator and persistence path.

The XLSX deterministic pass proposes source-located progress and milestone rows and validates them with the same group validator. A percent claim may carry its percentage as percent-shaped text or as a percent-formatted numeric cell (raw "0.125", display "12.5%") — the claim always carries the display shape the cited excerpt shows. Percent cells are eligible only when their column label proves progress (or is absent) and never names a risk metric, so "Weight: 8%" or a likelihood column stays model work. As-of variants come only from record-cued columns; baseline, forecast, and due columns cannot become record dates. The pass retains only accepted rows with proven scope; unsupported, ambiguous, and unstructured sources remain model work. Complete deterministic coverage requires every model-visible source in the group to be accounted for, not just spreadsheet locators. The model still processes cost, risk, and group analysis. Group retries and provider requests therefore remain possible; token savings are not guaranteed. On the 48-workbook demo corpus the pass now derives 408 progress and 248 milestone rows that previously fell entirely to the model (schema /39).
Fact citations and numeric consistency do not independently prove a model-selected `fact_type`. The provable subcase is enforced at the fact validator: a milestone fact whose whole claim is a progress-percentage statement (a percentage linked to explicit progress wording with no substantive content left once the schematic progress vocabulary is removed, using the same linkage proof as the progress-observation evidence rules) is rejected, retried as a correction, and — if the model keeps returning it — excluded with a quality warning and a failed, non-reusable group checkpoint. A milestone claim that merely mentions a progress figure alongside its own subject is kept, and claims that cannot be proven either way are left untouched: other mislabelings (a progress percentage typed as risk, issue, decision, or owner action) are not yet proven deterministically and still require reviewer judgment. Reviewers must not treat citation validity alone as semantic verification.
Quality-warning groups remain available to the current response for review but are checkpointed without a reusable result; retries re-extract them.
Checkpoint writes, lease renewals, downloads, and total worker processing log stage timings and outcomes with safe correlation IDs; database error details are not logged.

Job claims, leases, and recovery. Each attempt owns the job through a claim token plus a 30-minute lease; every durable write (checkpoints, suggestions, observations, publication) is verified against both in the same database transaction, so fencing holds regardless of anything the worker does. The worker renews the lease every 5 minutes during long checkpoint-free phases (parse/OCR, final summary, persist chain). Its provider guard is passed through that attempt only and compares a monotonic clock against the last known lease expiry, conservatively based on the start of the successful lease RPC; transient renewal errors do not extend that deadline, and delayed heartbeat timers cannot permit new provider work after it expires. A rejected renewal or known expiry revokes that attempt's guard and aborts its in-flight provider fetch when possible. The route returns `409 not_owned` and performs no later publish/retry/fail write; database fencing remains authoritative. Recovery is database-owned: a later claim repairs an expired lease (`worker_lease_expired`), requeues the job within `max_attempts`, and mints a fresh token. Completed extraction-group checkpoints are reused; an HTTP 429 stops starting further groups (at most the already in-flight bounded requests may finish), keeps deferred work retryable as `llm_provider_transient_failure`, and requeues with bounded backoff up to 300 s. A completed group is never re-sent on retry. Diagnosis of a historical user job must never claim a cause from these mechanics alone; they describe the mechanism, not what happened in a specific run.
Parser, classifier, per-group, and document-summary attempt timings are logged with job, project, and document IDs; group logs also include the group index and attempt number. Logs never include filenames, prompts, source text, model outputs, or credentials.

The document details panel shows latest job diagnostics independently of review warnings. A processing job can be manually requeued only when a recorded lease expiry is confirmed; the server passes the latest job ID, claim token, and raw expiry to a role-gated RPC that rechecks all three under row locks and compares expiry with the database clock. A renewal or reclaim between the read and RPC is rejected, the same job row is requeued without deleting published results or checkpoints, and the message does not claim the worker stopped. If the attempt limit is reached, the job is marked failed instead of bypassing the cap. The existing failed-job retry remains available but cannot replace a queued or processing attempt. A queued HTTP 429 remains deferred: recover provider quota and ensure worker polling is available instead of manually restarting the queued job.


The same group request also collects PMO cost evidence, whatever the document's primary type: an approved baseline amount, actual cost to date, committed cost, and an explicitly reported estimate at completion, each at project or work-package scope. No separate call or per-domain call is added. The model copies the source value exactly and cites a source ID; it never converts, totals, or compares. The worker rejects a value that is not present in its cited source, derives `normalized_amount` and `currency` deterministically from the source wording, and leaves both null when the wording is ambiguous (a scale word such as "million", a bare `$`, or an inconsistent separator layout). Normalization supplements the source value and never replaces it. Validated observations are persisted to `cost_observations` with the chunk index, a bounded excerpt, and the chunk's page/sheet location; a re-run replaces rows for the same content hash, parser version, and observation contract version. Accepting a baseline for comparison is a separate reviewer decision recorded in `cost_baselines`.

The same grouped extraction collects source-backed milestone, progress, and risk observations. Fenced cloud RPCs persist cost evidence and typed observations with their source hash, parser version, and `pmo-assurance-observations/1` contract version. Coverage is tracked separately for budget, schedule, progress, and risk; rejected or unprocessed evidence is not reported as absent. The document's current observation version is updated only after the observation and coverage write succeeds.

#### Risk snapshots across cut-offs

`claim_assurance_analysis` selects and returns the previous risk snapshot in its
atomic `prior_risk_snapshot` payload: the nearest strictly earlier eligible
review in the same project, using only that review's `current`-role documents.
The approved project baseline is never substituted. The combined reference
fingerprint captures review selection, linked document versions, risk
observations, coverage, and matching reviewer decisions; claim, finish,
currentness, and invalidation use the same snapshot. The application performs
no post-claim previous-source reads. Ticket 04's approved progress rule and
reference keys remain part of that same fingerprint and claim response.

Observation, coverage, and reviewer decision rows must match each document's
project, content hash, parser version, and contract version. Accepted and
corrected decisions are applied with attribution; rejected and stale-version
observations are excluded. Only project-scoped reviewer-accepted risk-ID and
scale mappings are applied, and mapping/reference fingerprints are retained.

Each risk row must state its own valid ISO source date for a temporal pair;
week/month-only, missing, reversed, or conflicting cut-offs remain gaps. A
group-level cut-off can support "new" only when every linked prior source has
processed risk coverage, a risk observation, and the same valid ISO cut-off.
Conflicting duplicate IDs are gaps, not first-row wins. "Increased" requires
comparable ordered snapshots, same or reviewer-mapped scales, and source
ratings; "closed" requires a comparable pair and source-stated closed status.
Missing observations stay "not reported", never closed. W5 IDs/citations and
W6/W7 comparisons are shown only when the extracted, versioned source supports
them. No Risk composite is produced.

Reviewers can accept, correct, or reject supported observations individually on the Assurance page, including before a document is linked to a review. Decisions retain the reviewer, reason, source version, and original observation; changed decisions invalidate dependent assessments. The observation-decision migration must be applied by the project owner before deployment.

Documents marked Needs Review are selectable only when coverage exists for their current source version. Processing warnings remain visible, and unprocessed domains remain evidence gaps, not absence, zero, or a green condition.

The grouped extraction path uses the `XASS_LLM_PROVIDER` selected in the worker environment: local Ollama, Ollama Cloud, OpenAI-compatible, Gemini, or Groq. Set `GEMINI_API_KEY` and `GEMINI_MODEL` for Gemini, or `GROQ_API_KEY` and `GROQ_MODEL` for Groq. Choose a Groq model available to the account; model access, pricing, and rate limits vary. Local Ollama keeps evidence on the machine; hosted providers receive the prompt and source text. A quota or rate-limit response (HTTP 429, like 408 and 5xx) is transient: the group stays retryable with its attempt count and error, and completed groups keep their reusable cached result. A later retry re-sends only groups that never completed. Deferred groups never become absent evidence; the document does not complete until every group has a validated result.

The per-document extraction ceiling is 32 groups (at most 96 parser chunks or about 320,000 source characters). Larger documents fail with an actionable Needs Review error; the original file is retained and later chunks are never silently dropped. Each group summary cites one or more relevant source IDs; citation coverage for every chunk is not required. The final document summary selects at most six of those citations. Invalid required evidence remains an explicit quality warning, never a complete high-confidence fallback.

PDF parsing is bounded to 200 pages, 64,000 extracted characters per page, and 320,000 characters total. Scanned-page OCR is limited to 20 pages per PDF. A breached limit fails the document rather than truncating it. Office ZIP packages are checked before XML expansion and limited to 25 MiB per member and 100 MiB total expanded content.

## Standalone local parser evaluation

From the repository root, run:

```bash
node tools/document-parser-eval.mjs
```

The runner calls `parseDocumentBuffer()` directly; it needs no application login, server, or database. It evaluates two selected PDFs and three representative XLSX workbooks from `SMART BUILDING/`, then rasterizes page 1 of `Komponen Wajib BGC.pdf` at 160 DPI to exercise the production PP-OCRv6 image route. Original PDF results report whether their pages also used OCR.

Requires installed Node dependencies, the local PP-OCRv6 setup above, and Ghostscript. Results go to `.local-evaluation/document-parser/`: `summary.json` contains parser versions, counts, warnings, OCR metadata, formula-cache statuses, and limits; each other JSON file contains full extracted chunks for manual review. Override the destination with `--output-dir PATH`. The output includes source text, stays local, and is git-ignored; treat it as sensitive.

This is a review harness, not an accuracy score: no ground-truth transcripts are supplied. Check OCR text and table reconstruction against the PDFs. XLSX formulas are not recalculated; cached values may be stale, and parser warnings require inspection. Any failed parse or OCR route exits non-zero.
